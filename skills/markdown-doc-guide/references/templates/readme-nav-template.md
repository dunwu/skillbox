# README 导航索引文档模板

> **适用范围**：模块/目录的 README.md 文件，作为文档站点的导航入口和文章索引。
> **核心定位**：帮助读者快速了解该领域的知识全貌，精准定位目标文章。
> **图表提示**：本模板以文本索引为主，一般不使用图表。

## Frontmatter

```yaml
---
title: [领域名称]
date: YYYY-MM-DD HH:mm:ss
categories:
  - [一级分类]
tags:
  - [标签]
permalink: /pages/[hash]/
hidden: true
index: false
---
```

**规范化写作指南**：

- 导航类 README 通常设置 `hidden: true` 和 `index: false`，避免被搜索引擎索引。
- `title` 直接使用领域名称，如 `Java`、`分布式`、`人工智能`。

## 文档标题

```markdown
# [领域名称]
```

## 领域概述（可选）

**章节内容意图**：对该技术领域进行全局性描述，帮助读者建立宏观认知。

**规范化写作指南**：

- 用 2-3 句话概述该领域的核心价值、技术体系和发展趋势。
- 聚焦"这个领域解决什么问题"，而非罗列具体技术。

## 知识域章节

```markdown
## [知识域名称]
```

**章节内容意图**：按知识域对文章进行分组，每个知识域包含章节描述和文章列表。

**规范化写作指南**：

- 知识域名称使用 `##` 二级标题。
- 每个知识域必须有引用块描述（`>`），作为该领域的精辟技术小结。
- 子知识域可使用 `###` 或 `####` 三级/四级标题。
- 知识域按认知递进排列：基础 → 进阶 → 高级 → 综合。

## 章节描述（引用块）

```markdown
> [精辟、专业的技术小结，概括该知识域的核心知识体系]
```

**章节内容意图**：为每个知识域提供一段精辟的技术概述，帮助读者快速判断该章节是否是自己需要的内容。

**规范化写作指南**：

- **长度**：1-3 句话，不超过 150 字。
- **内容要求**：
  - 概括该知识域涉及的核心技术、关键概念和知识脉络。
  - 使用专业术语，避免泛泛而谈的套话（如"很重要"、"值得学习"）。
  - 可适当提及技术之间的关联关系（如"这些技术构成了 Spring MVC 的底层规范基础"）。
- **禁止内容**：
  - 不使用"本章主要介绍"、"本章内容包括"等元描述。
  - 不罗列文章标题。

**模板示例**：

```markdown
> Java 并发专题从线程模型与内存模型（JMM）出发，系统梳理 `synchronized`/`Lock` 锁机制、`volatile` 语义、`java.util.concurrent` 工具包（线程池、并发容器、同步器），以及 `CompletableFuture` 异步编程范式。
```

## 文章列表

```markdown
- [文章标题](相对路径) - 关键词：`关键词1`、`关键词2`、`关键词3`
```

**章节内容意图**：列出该知识域下的所有文章，附带关键词帮助读者快速定位。

**规范化写作指南**：

- **链接格式**：`[显示文本](相对路径.md)`，路径使用相对路径。
- **关键词规范**：
  - 每篇文章关键词严格控制在 **5 个以内**。
  - 关键词选取标准：结合文章标题相关技术领域的热门关键词及文中词频综合判断。
  - 使用反引号包裹每个关键词，关键词之间用中文顿号（`、`）分隔。
  - 关键词格式：` - 关键词：` + 反引号关键词列表。
- **排序**：按认知递进排列（概念 → 原理 → 实践 → 面试）。

**模板示例**：

```markdown
- [Tomcat 快速入门](Tomcat/[Tomcat]快速入门.md) - 关键词：`Tomcat`、`Server 架构`、`Service`、`生命周期`、`server.xml`
- [Tomcat 连接器](Tomcat/[Tomcat]连接器.md) - 关键词：`NioEndpoint`、`Acceptor`、`Poller`、`NIO`、`SocketProcessor`
```

# [领域名称]

- [文章 2](路径/文章2.md) - 关键词：`关键词1`、`关键词2`

### [子知识域 A2]

- [文章 3](路径/文章3.md) - 关键词：`关键词1`、`关键词2`、`关键词3`

## [知识域 B]

## 多级 README 同步规范

**本节为文档编写指南**，不体现在最终文档中。

在 vuepress-theme-hope 等多级目录结构的文档站点中，同一份文章列表会在多个 README 中出现。修改时必须同步更新以下层级：

| 层级 | 路径示例 | 路径前缀示例 |
| :--- | :------- | :----------- |
| 子目录 README | `docs/01.Java/JavaCore/README.md` | 无前缀 |
| 中间层 README | `docs/01.Java/README.md` | `JavaCore/` |
| 根 docs README | `docs/README.md` | `01.Java/JavaCore/` |
| 工程根 README | `README.md` | `docs/01.Java/JavaCore/` |

**同步检查清单**：

- [ ] 所有章节描述（引用块）在各层级 README 中保持一致。
- [ ] 所有关键词在各层级 README 中保持一致。
- [ ] 路径前缀根据各层级正确调整。
- [ ] 文章标题和链接文本在各层级保持一致。

## 自检清单

- [ ] 每个知识域都有 `>` 引用块章节描述。
- [ ] 章节描述精辟专业，不使用"本章介绍"等元描述。
- [ ] 每篇文章都有关键词，且不超过 5 个。
- [ ] 关键词用反引号包裹，顿号分隔。
- [ ] 所有文章链接有效，路径前缀正确。
- [ ] 多级 README 内容同步一致。
- [ ] 中英文之间有空格，标点符号符合规范。
