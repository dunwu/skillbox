# 面试题文档模板

> **适用范围**：技术领域面试备战手册、面试知识点梳理文档。
> **核心定位**：面向资深技术专家的面试备战，每道题要求精炼、专业、直指核心。
> **图表提示**：对比类问题优先使用表格，流程类问题可使用 Mermaid。

## Frontmatter

```yaml
---
title: [技术领域] 面试
date: YYYY-MM-DD HH:mm:ss
categories:
  - [一级分类]
tags:
  - [标签]
permalink: /pages/[hash]/
---
```

## 文档标题

```markdown
# [技术领域] 面试
```

**规范化写作指南**：

- 标题简明扼要，直接点明技术领域，如 `# Java 并发面试`、`# Prompt 工程面试`。
- 不使用副标题或额外说明。

## 章节划分

```markdown
## [知识域名称]
```

**章节内容意图**：按知识域（Knowledge Domain）对面试题进行分组，使文档结构清晰，便于按主题复习。

**规范化写作指南**：

- 每个章节对应一个独立的知识子域，如"基础概念与核心组件"、"记忆、工具与规划"、"高级主题"。
- 章节按认知递进排列：基础概念 → 核心机制 → 高级应用 → 工程实践。
- 同一知识域的多篇文章（如并发一、二、三）应合并评估知识覆盖度，避免遗漏或重复。

## 面试题

```markdown
### 【难度】题目？⭐
```

**章节内容意图**：面试题是文档的最小单元，每道题包含题目、答案和总结三部分。

**规范化写作指南**：

- **难度分级**：必须标注，三选一：
  - `【简单】`：基础概念、定义辨析、常见工具使用。
  - `【中等】`：原理分析、机制对比、方案设计。
  - `【困难】`：架构决策、深度原理、工程实践中的复杂问题。
- **重要度标记**：使用 ⭐ 标记在题目末尾，最多 ⭐⭐⭐⭐⭐，最少无 ⭐。
  - ⭐⭐⭐⭐⭐：几乎必考的核心概念（如 CoT、RAG、并发与并行）。
  - ⭐⭐⭐⭐：高频考点，面试中大概率涉及。
  - ⭐⭐⭐：中等频率，体现深度理解。
  - ⭐⭐：低频但有区分度的知识点。
  - ⭐ 或无：补充性知识、冷门话题。
- **题目表述**：以问句结尾，清晰具体，避免模糊的"谈谈 XXX"式提问。

**模板示例**：

```markdown
### 【简单】什么是 AI Agent？它和直接调用大模型 API 有什么区别？⭐⭐⭐
```

## 答案正文

**章节内容意图**：精炼、专业地回答面试题，兼顾深度和可读性。

**规范化写作指南**：

- **开头直击要点**：第一句话给出核心定义或结论，不铺垫不绕弯。
- **结构化表达**：
  - 对比类问题 → 使用表格（维度 | A | B）。
  - 流程类问题 → 使用有序列表 + 关键步骤加粗。
  - 列举类问题 → 使用无序列表，要点不超过 5-7 个。
  - 原理类问题 → 先一句话总结，再展开细节。
- **术语规范**：
  - 专业术语用反引号包裹，如 `Function Calling`、`ReAct`、`CoT`。
  - 首次出现的缩写给出全称，如"RAG（Retrieval-Augmented Generation）"。
  - 重要概念可加粗强调。
- **代码示例**：仅在必要时提供，保持精简（不超过 10 行），使用正确的语言标注。
- **信息密度**：每段话都要有信息增量，删除"众所周知"、"不言而喻"等废话。

**模板示例**（对比类）：

```markdown
AI Agent（智能体）是以大语言模型（LLM）为"大脑"的自主智能系统。

**与直接调用大模型 API 的核心区别**：

| 维度         | AI Agent                          | 直接调用 LLM API              |
| :----------- | :-------------------------------- | :---------------------------- |
| **交互模式** | 多步骤自主循环（规划→执行→反思）  | 单次问答（指令→生成→用户执行） |
| **工具能力** | 自主调用外部工具（搜索、API 等）  | 仅生成文本，无法执行操作       |
| **记忆能力** | 具备短期/长期记忆，持续学习适应   | 无状态，每次独立交互           |
```

## 精辟总结

```markdown
> **总结**：[1-2 句话，直指问题核心，便于记忆]
```

**章节内容意图**：每道题答案末尾的一句话总结，是面试前快速复习的"记忆锚点"。

**规范化写作指南**：

- **长度**：严格控制在 1-2 句话，不超过 80 字。
- **风格**：
  - 使用类比增强记忆（如"MCP 之于 Agent，犹如 USB 之于外设"）。
  - 使用公式化表达（如"Agent = LLM + 规划 + 记忆 + 工具"）。
  - 使用对比式总结（如"ReAct 解决当下怎么想怎么做，Reflexion 解决这次失败了下次怎么改进"）。
- **格式**：使用引用块 `>` + **总结** 加粗标记。

**模板示例**：

```markdown
> **总结**：Agent 与传统 AI 的本质差异在于——传统 AI 执行预定义规则的单点任务，Agent 能理解自然语言指令，自主将复杂目标拆解为子任务，动态调用工具并反思优化。
```

## 知识覆盖度评估（文档编写指南）

**本章节不体现在最终文档中**，仅供文档编写者在创建/优化面试题文档时参考。

**评估流程**：

1. **汇总同域题目**：将同一目录下同领域的所有面试题文章合并审视（如并发一、二、三）。
2. **对标权威来源**：对照以下来源检查是否覆盖核心知识点：
   - 该领域的经典书籍章节目录。
   - 官方文档的核心概念列表。
   - 权威技术社区的热门面试总结。
3. **查漏补缺**：发现缺失的热门/重要问题必须补齐，确保不遗漏关键知识点。
4. **去重合并**：同一知识点的不同表述应合并，避免重复题目。

**信息来源要求**：

- 优先来源：官方文档、经典书籍、权威技术博客（如 InfoQ、掘金、Medium）。
- 可接受来源：知名技术大牛的公开分享、高质量开源项目的文档。
- 禁止引入：无法验证的内容、道听途说的结论、过时已废弃的技术细节。

## 自检清单

文档编写完成后，逐项确认：

- [ ] 每道题都有 `【难度】` 标记（简单/中等/困难）。
- [ ] 每道题都有 ⭐ 重要度标记（0-5 颗）。
- [ ] 每道题都有 `> **总结**：` 引用块。
- [ ] 答案开头直击要点，不铺垫不绕弯。
- [ ] 对比类问题使用表格，流程类问题使用有序列表。
- [ ] 专业术语用反引号包裹，首次缩写给出全称。
- [ ] 无重复题目（同一知识点只出现一次）。
- [ ] 同领域文章合并评估，无重要知识点遗漏。
- [ ] 所有内容来源可信（官方文档/经典书籍/权威分享）。
- [ ] Frontmatter 格式正确，无 YAML 语法错误。
