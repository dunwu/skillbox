# Methodology Training Guide

> This file defines Mode ③ "Skill Training" — interactive drills that build the user's **own** ability to understand and comprehensively apply the 51 methods. It is distinct from Mode ① (the coach diagnoses and selects *for* the user) and Mode ② (the coach walks the user *through* one method): in training, **the user produces the answer, and the coach produces feedback**. The deliverable is not a solution but a *capability*.
>
> **Target ability = five sub-skills**: ① Locate the stage, ② Select the method, ③ Land the first action, ④ Recall the boundary, ⑤ Chain methods for a complex scenario. "Understanding" maps to ② and ④ (knowing what a method is, and when it fails); "Comprehensive application" maps to ① ③ ⑤ (using and combining methods in real scenarios).
>
> **Universal rules**: structure the journey first (§0 learning plan), then drill; one drill per round; present the scenario → wait for the user's answers → give feedback in the fixed format (§5); difficulty climbs Level 1→5 (§4); never give the answer before the user attempts it.

## 0. Learning Plan

> Before running drills, help the user structure the *journey* of learning the 51 methods — which to learn first, how much time, how to review, how to consolidate. §2–§8 are the *micro* loop (one round); this section is the *macro* plan (weeks). The plan itself is a hypothesis (the skill's Red Line 4) — verify with data, adjust rather than stack. 🔴 Never promise a fixed number of weeks as if it were scientific; the calendar is a container, the correct-rate + real-world application is the measure.

**How to use this table** (Cornell retrieval practice): cover the right column (notes), answer the cue-column questions from memory; re-read the gaps in [methodology.md](methodology.md); self-test again at 1 / 3 / 7 / 15 / 30 days. What works is not the format itself but the "提炼问题 + 遮答自测" retrieval practice.

## 1. When to Enter Training Mode

| Trigger signal | Action |
| --- | --- |
| User asks to be trained / drilled / tested: "训练我", "考考我", "出题", "drill me", "test me", "quiz me" | Enter Mode ③ |
| User wants to *learn the methods themselves* rather than be handed an answer ("我想掌握这些方法论", "怎么才能熟练运用") | Enter Mode ③, confirm before starting |
| User asks "how do I get better at using methodologies" / "怎么练判断力" | Offer Mode ③, confirm before starting |

🔴 **CHECKPOINT** — when intent is ambiguous between "give me the answer" (Mode ①) and "train me" (Mode ③), ask one clarifying question; never assume. When the user corrects a diagnosis or rejects the drill, return to stage location / re-state the drill and wait.

## 2. Drill Format (Core Loop)

Each round is three moves:

1. **Coach presents a scenario** — a realistic, specific situation with one primary bottleneck and (at higher levels) subtle misleading signals. End by asking the three questions. The scenario MUST embed the minimum facts needed to answer: current metrics, constraints, the known-item list, deadline pressure. **If the learner would have to invent numbers to answer, the scenario is under-specified — that is the coach's defect, not the learner's.** For goal-setting drills (SMART), ship a fact card with baseline data.
2. **User answers three questions**:
   - **Locate** — which stage are they stuck in? (Direction / Execution / Improvement / Learning / Communication; Learning subdivides into Understand · Memorize · Apply · Curate, Execution into Habit · Focus, Communication into Structure · Narrative).
   - **Select** — which method (from the three quick-reference tables in methodology.md)?
   - **Land** — the first concrete action tomorrow morning (time + verb + object + deliverable), not a principle.
3. **Coach gives feedback** in the fixed format (§5).

> **Stage boundary (drill this in L1)**: prioritization / trade-offs ("urgent crowds out important", "the list keeps growing") is an **Execution** problem, not Direction. Direction = no goal at all ("不知道该学什么 / 往哪走"). Execution = has a goal but can't finish / can't arrange — including prioritization. This boundary is a frequent error (the coach itself tripped on it once); always resolve it to Execution.
>
> **Landing rubric (drill this in L2+)**: a landable action = **time + verb + object + deliverable**, executable tomorrow morning. Not landable = principle verbs like 梳理 / 排序 / 优化 / 明确 ("深挖轻重缓急" / "整理清楚待办" / "主动回忆"). A landable landing also performs the method's "soul actions" — e.g. the Eisenhower Matrix must Delete Q4 + Delegate Q3 + Protect Q2, not just "rank the list".

🔴 **CHECKPOINT** — always wait for the user's answer before giving feedback. Do not pre-empt, do not hint, do not reveal the answer "for reference" before the user attempts. The retrieval-practice effect is the whole point.

## 3. Five Question Types (the training toolkit)

| # | Type | Trains sub-skill | Scenario format | What the user answers |
| --- | --- | --- | --- | --- |
| ① | Locate | ① Locate the stage | A pain described in symptoms | Name the primary stage + why, in one sentence |
| ② | Select | ② Select the method | A stage + symptom ("理解了但讲不清") | Name the method + evidence grade (S/A/B/C) |
| ③ | Land | ③ Land the first action | A method + scenario | The first concrete action (time + verb + object + deliverable) |
| ④ | Boundary | ④ Recall the boundary | "When does method X fail?" | The failure form / boundary in the user's own words |
| ⑤ | Chain | ⑤ Chain methods | A complex multi-stage scenario (≥2 stages) | A 3–5 stage combination chain + the handoff logic |

Types ①②③ combine into the standard three-question drill; ④ and ⑤ are standalone drills used once the user has covered enough methods. Always pull the method's `Boundary` field from methodology.md; never improvise a boundary from memory.

## 4. Difficulty Progression

| Level | Content | Question types | Success bar |
| --- | --- | --- | --- |
| 1 Warm-up | Stage location only — one scenario, name the stage | ① | Confirm the "locate-before-select" reflex; only one stage named, not four |
| 2 Execution | Execution methods (Eisenhower Matrix / SMART / Pomodoro·Time Blocking / Energy Management / Deep Work / GTD / Pareto / AAR·PDCA…) | ①②③ | Correct stage + method + a landable first step |
| 3 Learning | Learning methods (Feynman / Spaced Repetition / Active Recall / Deliberate Practice / Interleaving / Output-Driven Input / Zettelkasten…) | ①②③④ | Above + can state the boundary |
| 4 Thinking | Thinking methods (Structured Thinking / Pyramid Principle / MECE / SCQA / 5W2H / 5 Whys…) | ①②③④ | Above + no cross-category confusion (e.g. forcing the Eisenhower Matrix onto a thinking / curation problem) |
| 5 Combination | Complex multi-stage scenarios; the seven combination chains | ⑤ | A 3–5 stage chain with handoff logic + a recheck plan |

**Advance rule**: stay at a level until the user passes it (see §8); move up one level at a time; do not skip. If the user struggles at a level, first diagnose *which sub-skill* is weak, not just "wrong", and drill that sub-skill.

## 5. Feedback Standard (Mandatory Format)

After the user answers, the coach MUST give feedback in this structure. This is the anti-"theory-only" guarantee:

```
① 对错判定 — right / wrong / partially right, in one line.
② 理清思路 — the method chain this scenario needs (e.g. 四象限 → SMART → 番茄/时间块 → AAR),
             and WHY each link is there (each link solves one stage; no overlap, no gap).
③ 具体案例落地 — a concrete worked example for THIS scenario: a named person, real tasks,
                 tasks sorted into the quadrants / tables, a calendar block, the rewritten
                 SMART goal, the AAR table. Artifacts, not principles.
④ 边界警示 — the failure form of the chosen method in this scenario (required; from the
             knowledge base's Boundary field).
⑤ 术语解释 — any shorthand used (Q1/Q2/Q3/Q4, SMART letters, S/A/B/C, P99…) must be
             defined inline on first use. Assume the user does not know the shorthand.
```

🔴 **CHECKPOINT** — if the user's answer was wrong, ② and ③ still explain the *correct* chain with a concrete case; never stop at "wrong, the answer is X". Feedback that is theory-only, or that uses undefined jargon, is a training red-line violation.

**④ Boundary ≠ Mechanism (teach this early)**: Mechanism = why it works (its logic); Boundary = when it fails (its failure condition). A boundary answer that describes *how it works* ("都是对抗遗忘曲线") or is too vague ("不适用于其他场景") is a fail. A passing boundary names a **specific failure scenario**. Standard three questions: ① what is it good / bad at? ② in what scenario does it backfire? ③ what precondition, if unmet, makes it useless?

## 6. Training Red Lines

- ❌ Give the answer before the user attempts (kills the retrieval-practice effect)
- ❌ Feedback that is theory-only ("你要学会排优先级") with no concrete case
- ❌ Use unexplained jargon (Q1/Q2/Q3/Q4, S/A/B/C, 2PC…) — define on first use
- ❌ Train more than one method per round, or stack >5 methods in a chain
- ❌ Grade a C-grade method as empirically optimal during feedback
- ❌ Skip the boundary warning in feedback
- ❌ Promise a fixed number of weeks/days to mastery ("学 6 周就能掌握") — success is measured by correct-rate + real application, not calendar time
- ❌ Force the learner to fabricate figures in a data-free scenario, then mark placeholders (XX) wrong — either supply the facts, or accept "metric form + TBD + how to measure" as the correct answer
- ❌ Present the coach's own invented figures as "the" answer without labeling them `[示例数据]`
- ❌ Move to the next level before the user passes the current one

## 7. Worked Example (Level 2 · Execution, locate + select + land)

**Coach presents:**

> 你最近一周：每天忙到 11 点，但回头答不上来干成了什么；待办清单越列越长；领导临时塞的活总打乱计划；想学的新技术一直没时间碰。
>
> 请回答三问：① 卡在哪个环节？② 用什么方法？③ 明天早上的第一个具体动作？

**User answers** (example of a common miss):

> ① 定向、执行、改进、学习（四个都卡）。② 四象限。③ 早上整理清楚今日待办。

**Coach feedback:**

> **① 对错判定**：定位错（一次列四个 = 没定位）；选法对；落地不合格（只列清单，没取舍、没保护）。
>
> **② 理清思路**：这个场景主环节是**「执行」**——具体是执行环节的**取舍 / 优先级**问题（有目标但做不完、不会排优先级）。方法是四象限（取舍），保护 Q2 还要加时间块。链：**四象限 → SMART → 时间块 → AAR**——四象限决定「做什么、不做什么」，SMART 把 Q2 的模糊目标变具体，时间块把 Q2 锁进日历，AAR 傍晚校准计划与实际。
>
> **③ 具体案例落地**（研发小王，周一早晨）：
> - 列全量清单 6 项 → 每项问两问（贡献长期目标吗？有死线吗？）→ 落象限：线上 bug = Q1 Do；明天汇报 PPT = Q1 Do；学 Go = Q2 Decide 锁进 14:00–15:30；下月才做的评审会 = Q3 Delegate 只要纪要；review 代码 / 刷新闻 = Q4 Delete。
> - 四象限的 4D：Do / Decide / Delegate / Delete。只 Do 不 Delete，清单只会越列越长。
> - SMART 改写「学 Go」：写一个 300 行命令行小工具、能独立跑通、每周 5 小时、12 月 20 日前、服务于全栈长期目标。
> - 傍晚 AAR 四问：预期 vs 实际 vs 差异原因 vs 下次改什么。
>
> **④ 边界警示**：「重要」若不绑定具体目标，矩阵退化成主观排序；Q2 时段必须作为固定日程保护，否则被紧急项持续挤占。
>
> **⑤ 术语解释**：Q1 = 重要且紧急，Q2 = 重要不紧急（决定长期价值的），Q3 = 紧急不重要，Q4 = 不紧急不重要。判断只问两问：贡献长期目标吗？有死线吗？

## 8. Assessment & Exit

- **Per-round**: mark Locate / Select / Land / Boundary each ✓ / ✗. A round passes when Locate + Select are both correct, Land is landable (time + verb + object + deliverable), and (from L3) Boundary names a specific failure scenario.
- **Data-availability rule**: when the learner has no data, grade a goal statement on its **metric form** (metric name + measurement basis + threshold source), not on its values. "TBD + how to collect it" is a pass; inventing numbers is a fail; "例如 / XX / 有待量化" is a pass only if the metric form is named.
- **Retry rule**: a failed part gets at most **2 retries**. After 2 misses on the same part, give the full model answer, mark it "not yet mastered", and move on (or downgrade a level) — do not loop indefinitely.
- **Per-level**: pass when the user answers one full drill correctly (≤2 retries per part); then move up one level. The "3 consecutive rounds" bar is for independent self-practice, not for a coach-led walkthrough.
- **Exit (mastery)**: pass a Level-5 Combination round AND the user has applied ≥1 method in real work that week and can describe the result.
- **Recheck card (4 elements, attach on completion)**: ① Metric (observable metric) ② Baseline (current data, or "TBD" + a collection method) ③ Recheck date (~30 days) ④ Adjustment rule (ineffective → swap a method / drop a stage, **do not stack**). A learner answering "复测方案 = PDCA" (naming a method instead of the card) is a known miss — correct it.
- **Recheck**: training itself is a hypothesis. Every ~2 weeks, check the user's correct-rate trend and real-application count. If stuck, re-diagnose *which sub-skill* is weak (location? selection? landing? boundary? chaining?) and drill that one — do not push more methods.

## 9. Common Learner Failure Patterns (drill responses)

These recur across learners; recognize them and respond as prescribed (observed in field runs):

| # | Pattern | Symptom | Prescribed coach response |
| --- | --- | --- | --- |
| 1 | Jump-to-solution | Answers with advice ("学习要带目标") instead of locating the stage | "你把「怎么学才对」当成了「卡在哪」。先只答：卡在哪个环节？" |
| 2 | Abstract landing | Uses principle verbs 梳理 / 排序 / 优化 / 明确 ("深挖轻重缓急") | Require "time + verb + object + deliverable"; show the model on concrete items; refuse 梳理 / 排序 / 优化 |
| 3 | Method stacking | Lists 4–5 methods for one stage ("原子笔记、主动回忆、间隔重复、输出、反馈") | Enforce one primary method per stage; map the sub-stage to its 1–2 methods (Memorize → Spaced Repetition + Active Recall) |
| 4 | Fabricated method | Uses a method not in the knowledge base ("头脑风暴") | Red Line 5: label it "not in the knowledge base"; substitute the catalogued method (Pre-mortem) |
| 5 | Vague boundary | "不知道" / "不适用于其他场景" / describes mechanism not boundary | Contrast mechanism vs boundary; require a specific failure scenario ("发散性讨论") |
| 6 | Recheck-as-method | Answers "复测方案 = PDCA" (a method, not the recheck card) | Require the 4-element recheck card (Metric / Baseline / Date / Adjustment rule) |

| 7 | Forced fabrication | Writes `XX ms → XX ms` / "例如优化服务器性能" because the scenario gave no data | Concede the scenario was under-specified. Accept the **metric form** (metric + measurement basis + threshold source + value TBD) as valid; grade only the missing "where to get the number" step. Never demand invented figures |

Coaching rule: when a pattern recurs ≥2 times across rounds, stop drilling new content and teach that pattern directly (a one-off "补课"), then resume.

> **Relationship to the rest of the skill**: §2–§6 reference the judgment filters, quick-reference tables, method sections, and Boundary fields in [methodology.md](methodology.md); §7's chain and handoff logic follow the "Combination Quick Reference" and the Mode ①/② rules in the skill's SKILL.md. Training never fabricates methods or evidence — it draws only from the knowledge base.
